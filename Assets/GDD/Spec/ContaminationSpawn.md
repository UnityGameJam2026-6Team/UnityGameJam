# 데이터와 생성 스펙

- 상태: 확정
- 근거 문서: GDD §3.1–3.2, §4, §6–8, §11 / `Undecided.md` U1·U3·U19·U20 / `FacilityLayout.md` 생성 지점 용량표
- 담당: A2 · A 레인
- 네임스페이스: `UnityGameJam.Data`, `UnityGameJam.Cleaning`

## 목적

판마다 구역별 오염의 종류, 수량, 위치를 바꾸면서 시설 전체의 시작 가중 오염량을 정한 범위에 맞춘다. 게임 규칙과 작업자 수치는 ScriptableObject에 저장하고, 실제 세션에서 사용하는 연결은 M1에서 진행한다.

## 입력과 출력

| 구분 | 이름 | 설명 |
|---|---|---|
| 입력 | `FacilityLayout` | 판정 구역 9개, 구역·유형별 생성 지점, 작은 물건 제자리 슬롯 |
| 입력 | `ContaminationTypeSO` | 네 유형의 가중치와 플레이어의 작업 시간 |
| 입력 | `ZoneSpawnTableSO` | 구역·유형별 최소·최대 개수, 시설 시작 가중치 범위와 최대 추첨 횟수 |
| 입력 | `IRandom` | 시드를 지정할 수 있는 난수 공급원 |
| 출력 | `ContaminationItem` 목록 | A1 레지스트리에 넘길 시작 오염 개체 |

## 규칙

1. 판 시작에만 오염을 생성한다. 각 구역에는 최소 1개의 오염이 있어야 한다. 구역·유형별 개수는 표에 정의한 최소~최대에서 양 끝을 포함해 균등하게 뽑는다. 유형별 개수 범위로 GDD §3.2의 상대적인 생성 비율을 표현한다.
2. 시설 전체의 가중 오염량을 계산해 허용 범위에 든 배정만 채택한다. 범위를 벗어난 배정은 버리고 최대 추첨 횟수까지 다시 뽑는다.
3. 승인된 배정에서 구역·유형이 일치하는 위치를 중복 없이 고른다. 작은 물건마다 같은 구역의 제자리 슬롯을 하나씩 중복 없이 배정한다(U3).
4. 신규 시드를 사용한 독립 호출은 서로 영향을 주지 않는다. 같은 레이아웃, 설정, 시드로 시작하면 개수·위치·ID·슬롯 배정이 같은 목록을 반환한다.
5. 판과 청소에 쓰는 수치는 `GameRuleSO`, `ContaminationTypeSO`, `ZoneSpawnTableSO`, `WorkerStatsSO`의 에셋 값에서 읽는다.

## 예외 처리

- 필수 구역 또는 유형의 표가 없거나 중복되거나, 최소·최대가 맞지 않거나, 구역별 최소 개수의 합이 0이거나, 최댓값을 수용할 생성 지점·제자리 슬롯이 부족하면 설정 오류로 보고한다. 존재하지 않는 위치에 생성하거나 설정을 조용히 줄이지 않는다.
- 모든 추첨이 시설 가중치 범위를 벗어나면 설정 오류를 반환한다. 일부만 생성된 목록은 세션에 전하지 않는다. 범위와 최대 추첨 횟수는 `ZoneSpawnTableSO`에서 읽는다.

## 설계

| 파일 또는 에셋 | 역할 |
|---|---|
| `Runtime/Data/GameRuleSO.cs` | 판 시간, 구역·시설 청결도 기준, 제안과 통보 시간, API 대기 한도, 상호작용 거리 |
| `Runtime/Data/ContaminationTypeSO.cs` | 오염 유형별 가중치, 플레이어 물걸레질 시간 |
| `Runtime/Data/ZoneSpawnTableSO.cs` | 구역·유형별 개수 범위, 시설 전체 가중치 범위와 재추첨 한도 |
| `Runtime/Data/WorkerStatsSO.cs` | 작업자별 이동 속도와 필요 작업 시간, 운반 감속, U1 능력 |
| `Runtime/Cleaning/IRandom.cs`, `SeededRandom.cs` | 범위 난수 인터페이스와 시드 기반 구현 |
| `Runtime/Cleaning/ContaminationSpawner.cs` | 설정 검증, 수량 추첨, 위치·슬롯 배정, 개체 반환 |
| `3_Data/ScriptableObject/` | 위 SO 4종의 에셋. `WorkerStatsSO`는 작업자별 1개씩 둔다. |

수량 배정을 채택한 뒤 생성 위치와 슬롯을 고른다. 개체 목록은 고정된 구역·유형 순서로 구성한다. `ContaminationRegistry`와 `CleanlinessCalculator`는 M1에서 이 목록을 받아 시작 상태를 만든다.

## 미정 사항과 참조 값

### 승인된 첫 플레이테스트 기본값 (U19)

시설 전체 시작 가중치 허용 범위는 **170~200**, 최대 추첨 횟수는 **32회**다. 구역별 개수 범위는 아래와 같으며, 모두 현재 시설 생성 지점의 용량 안이다.

| 구역 | 무거운 잔해 | 일반 쓰레기 | 어질러진 작은 물건 | 바닥 얼룩 |
|---|---:|---:|---:|---:|
| 1층 로비 | 0~1 | 3~5 | 0~1 | 3~5 |
| 창고 | 2~4 | 1~3 | 0~1 | 0~2 |
| 다목적실 | 0~1 | 3~5 | 0~1 | 2~4 |
| 휴게실 | 0~1 | 2~4 | 2~4 | 3~5 |
| 2층 로비 | 0~1 | 3~5 | 0~1 | 3~5 |
| 작업실 | 0~2 | 1~3 | 3~5 | 0~1 |
| 회의실 | 1~3 | 1~3 | 1~3 | 0~1 |
| 3층 로비 | 0~1 | 3~5 | 0~1 | 3~5 |
| 간부실 | 0~2 | 4~6 | 3~5 | 3~5 |

| 데이터 | 확정값 | 첫 플레이테스트 기본값 |
|---|---|---|
| `GameRuleSO` | 판 180초, 구역 60%, 시설 85%, 제안 응답 7초 | 통보 4초, API 대기 한도 2초, 상호작용 거리 1.5m(현재 B2 설정과 동일) |
| `ContaminationTypeSO` | 무거운 잔해 4, 일반 쓰레기 3, 어질러진 작은 물건 2, 바닥 얼룩 1 | 플레이어 물걸레질 2초(현재 가짜 판과 동일) |
| `WorkerStatsSO` | U1 능력 표, 플레이어의 무거운 잔해 운반 속도 배율 0.5 | 아래 작업자별 표 |

| 플레이어 | 4.0 | `ContaminationTypeSO` 참조 | 무거운 잔해 운반 배율 0.5 |

계단 시간과 순찰 경로는 시설 측에서 제공하며, A2 스폰 수치에는 들어가지 않는다.
