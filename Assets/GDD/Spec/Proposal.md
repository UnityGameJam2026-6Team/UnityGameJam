# 제안 대기열과 대사 스펙

- 상태: 확정
- 근거: GDD §6·§9, U6·U10·U15·U16, A2의 `GameRuleSO`
- 네임스페이스: `UnityGameJam.Proposal`

## 목적

졸개의 다음 방 제안과 복귀·배출 안내를 계약의 메시지 목록으로 보낸다. 시간 제한과 재배정에 맞춰 어떤 제안이 현재 유효한지 정한다.

## 입력과 출력

졸개 ID, 배정 ID, 후보 방, 관찰에서 확인한 사실, 판 경과 시간, 대사 공급자를 입력받는다. `ActiveMessages`, `MessagesChanged`, 승인·보류 결과를 계약을 통해 제공한다.

## 규칙

1. 제안은 표시 순간부터 각각 7초를 센다. 승인·보류는 가장 오래된 활성 제안에 적용한다. 통보는 입력 대상에서 빠지고 `GameRuleSO`의 시간 동안 표시된다.
2. 같은 졸개의 현재 배정에는 제안 한 건만 표시한다. 재배정이나 판 종료로 무효화된 요청의 응답은 버린다. 응답의 목적지가 후보에 없거나, 오류·시간 한도 초과면 후보와 확인된 사실을 사용해 기본 대사를 한 번 표시한다.
3. 종별 대사는 게임에서 작성한다. Decisions API 공급자는 유효한 방과 대사 조합 하나를 고르며, 설정이 없거나 선택에 실패하면 기본 공급자가 첫 후보와 기본 대사를 쓴다. 확인되지 않은 오염과 청소 완료 사실은 대사에 넣지 않는다.
4. 대면 배정 패널이 열린 동안 승인·보류 입력은 받지 않되 제안 시간은 계속 흐른다(U10). 만료는 보류로 처리한다. 판 마감과 같은 틱의 순서는 A7에서 정한다(U15).
5. 후보가 없으면 복귀 통보만 보낸다. 헬하운드 배출 중과 적치물 없음은 사유별로 통보한다(U16). 방 정보를 새로 교환하면 졸개 두 이름을 담은 통보를 제안 HUD에 표시한다. 같은 조합의 통보는 표시 시간 동안 한 건으로 묶는다.

6. 졸개가 새 작업을 찾을 때 본인 또는 실제로 가까이 있는 동료가 관찰한 서로 다른 작업을 묶어 제안할 수 있다. 작업 중 발견한 일을 혼자 처리할 수 없으면 먼저 역할 분담을 제안할 수 있으며, 보류되면 기존 방으로 돌아가 작업을 이어간다. 가까운 동료가 이미 그 방을 맡았고 해당 작업을 할 수 있으면 각자 배정된 방에서 작업을 이어간다. 졸개끼리는 같은 방에서 분업하고, 플레이어에게는 플레이어가 있는 층에서 수행할 수 있는 작업을 부탁한다. Decisions API는 이미 만들 수 있는 계획 중 하나를 고른다.
7. 합동 작업 승인은 두 대상과 참가자의 배정·상태를 다시 확인한 뒤 각 졸개에게 다른 작업을 맡긴다. 플레이어 도움 요청을 승인하면 졸개의 작업을 시작하고 부탁을 HUD에 남긴다. 상황이 바뀌면 다른 제안을 찾는다. 플레이어에게 도움을 제안하거나 승인하기 전에 손에 든 물건, 걸레 상태, 작업 중 여부와 같은 층의 도구 확보 가능 여부를 확인한다.
8. 미확인 방 탐색은 앞서 배정된 작업자가 있는 방을 피한다. 제안이 표시된 뒤 상황이 바뀔 수 있으므로 승인할 때도 다시 확인한다. 알려진 작업을 돕는 이동은 계속 가능하다.
9. 합동 작업 후보는 두 작업이 점수에 반영되기까지 걸리는 예상 시간을 비교한다. 현재 위치에서 이동하는 시간, 계단 통과, 걸레 대여·반납, 걸레질, 슬라임의 다음 소화 가능 시점, 운반과 헬하운드의 다음 배출 가능 시점을 반영한다. 남은 판 시간 안에 두 작업이 끝날 수 있는 후보를 API에 보낸다.
10. 일반 이동 제안은 기존 종이색을 쓰고, 졸개 협업과 플레이어 도움 요청은 각자 다른 색과 제목을 쓴다. 대사 속 방 이름을 별도 색으로 강조한다.

## 설계

`ProposalQueue`가 메시지 ID와 수명을 관리한다. `IProposalDialogueProvider`와 기본 공급자는 요청·응답 경계를 제공한다. `MatchSimulation`에서 배정 ID와 실제 상호작용을 연결한다.

## Windows 전시 빌드

Windows 빌드에서도 에디터와 같은 Decisions API 공급자를 사용한다. 전시 PC에서 `OPENAI_API_KEY`를 실행 환경에 설정하거나, 실행 파일과 같은 폴더에 키만 담은 `.openai-api-key`를 둔다. 환경 변수를 우선 읽는다. 에디터의 키 파일은 프로젝트 루트에서 읽는다. 전시 PC에서 키를 설정하고 공유용 빌드 파일에는 키 파일을 포함하지 않는다.

키가 없거나 요청이 실패하면 기본 제안 공급자로 진행한다.
