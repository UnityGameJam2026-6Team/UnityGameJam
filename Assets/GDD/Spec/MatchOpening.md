# 판 시작 오프닝 스펙

- 상태 **확정**
- 담당 **B 레인 월드·표현**
- 근거 **GDD §2 시설과 시작 위치, §9 HUD 및 입력**, `FacilityLayout.md`, `MatchFlow.md`, `Hud.md`

## 목적

새 판이 열리면 1층 로비에서 플레이어와 일반 졸개 네 마리가 마주 선다. 화면 중앙에 `5 → 4 → 3 → 2 → 1`을 크게 표시하고 숫자마다 카메라 구도를 바꾼다. 마지막 숫자가 사라지는 순간 탑다운 조작과 `03:00` 타이머가 시작된다.

## 현재 구조

- `FL_Floor1`의 플레이어 시작점은 로컬 `(X, Z) = (0, −2)`다. 일반 졸개는 `X = ±2`, `Z = −4, −6`의 2×2이고 헬하운드는 현관 `(-4, -12)`에 있다. `MatchBootstrap`은 캐릭터를 모두 같은 기본 회전으로 만든다.
- `MatchBootstrap`은 캐릭터, 판, 오염 외형을 준비한 뒤 다음 프레임에 `Session.StartMatch()`를 호출한다. `Ready`에서 시뮬레이션과 플레이어 이동·상호작용은 대기한다. `FacilityHud`는 세션의 남은 시간을 표시한다.
- `FloorCameraFollow`가 한 대의 카메라를 갱신한다. `StartPositions`는 졸개가 작업 후 로비로 돌아갈 때도 사용된다.

## 규칙과 연출

1. 플레이어는 기존 시작점에 세우고, 플레이어 시작점 앞쪽에 일반 졸개 네 마리를 배치한다. 플레이어는 대열 중앙을, 졸개는 각각 플레이어를 바라본다. 기본 탑다운 화면 왼쪽부터 고블린·오크·스켈레톤·슬라임 순서다. 아래 그림은 1층 로컬 좌표 초안이며 실제 간격은 NavMesh와 모델 폭을 확인한 뒤 조정한다. 헬하운드는 현관에서 대기하고 기존 `StartPositions`는 복귀에 계속 사용한다.

   ```text
                          플레이어 (0, −2)
                                  ↓
                    ↗          ↗     ↖          ↖
                 고블린       오크   스켈레톤     슬라임
                  x −3        x −1    x +1        x +3
                               z = −5
   ```

2. 로비와 캐릭터가 준비되면 중앙에 큰 숫자 `5`를 바로 표시한다. 한 숫자당 1초이며 숫자와 카메라는 같은 경과 시간을 사용한다. 숫자가 바뀔 때 짧게 커졌다가 원래 크기로 돌아오고, 중앙 위치와 가독성은 유지한다. 오프닝 동안 게임 HUD는 숨기고 Tab을 포함한 게임 입력은 대기시킨다.

   | 시점 | 중앙 숫자 | 카메라 |
   |---|---:|---|
   | 0–1초 | 5 | 높은 와이드 샷에서 수직으로 하강하며 로비와 대열 전체를 보여 준다. |
   | 1–2초 | 4 | 플레이어 어깨 너머로 짧게 접근하며 네 졸개의 정면을 보여 준다. |
   | 2–3초 | 3 | 졸개 쪽에서 플레이어 상반신을 잡는 고정 리버스 샷. 얼굴은 중앙 숫자 오른쪽에 둔다. |
   | 3–4초 | 2 | 측면에서 짧게 횡이동하며 플레이어와 대열을 한 화면에 잡는다. |
   | 4–5초 | 1 | 측면 샷 끝에서 끊김 없이 올라가 기존 탑다운 위치와 각도에 맞춘다. |
   | 5초 |  | 숫자를 숨기고 탑다운 추적, 게임 HUD, 조작과 `03:00`을 시작한다. |

   4에서 3으로 컷할 때 플레이어와 대열을 잇는 시선 축의 같은 쪽에서 반대편 피사체를 보여 준다. 카메라는 5부터 2까지 축 한쪽에 머물고 1의 끝에서 기존 탑다운 위치에 닿는다.

3. 오프닝 동안 세션은 `Ready`로 두고 게임 시간, 졸개 판단과 작업을 진행하지 않는다. 마지막 카메라 자세를 탑다운 구도에 맞춘 뒤 `StartMatch()`와 `MatchStarted`를 각각 한 번 호출한다. 첫 게임 프레임에 `03:00`을 보여 주고 다음 프레임부터 판 시간을 차감한다.
4. 타이틀에서 시작할 때와 결과 화면에서 `다시 하기` 또는 `R`로 새 판을 열 때 같은 흐름을 적용한다. 카메라는 1층 로비에서 움직이며 방 공개 여부는 기존 플레이어 방문 규칙을 따른다.

## 설계와 구현 순서

| 순서 | 위치 | 작업 |
|---:|---|---|
| 1 | `MatchBootstrap`, `ViewSettingsSO` | 일반 졸개 네 마리의 출발 위치와 방향을 생성 전에 계산한다. 오프닝 5초 동안 `Ready`를 유지하고 시작 호출을 마지막으로 옮긴다. 씬에 저작된 시작점은 기존 복귀 데이터로 사용한다. |
| 2 | `FloorCameraFollow`, `ViewSettings.asset` | 기존 카메라에 오프닝 구도를 추가한다. 구도별 위치와 초점을 1층 로비 기준으로 조정하고, `1`의 끝을 기존 추적 자세와 맞춘다. 카메라의 Transform은 `FloorCameraFollow`에서 갱신한다. |
| 3 | `FacilityHud`, `MinionStatusPanel`, `UI_HudRoot` | 중앙의 Image에 기존 마왕 타이머의 빨간 숫자 스프라이트를 연결한다. HUD와 그 입력을 오프닝 동안 대기시키고 판이 시작될 때 표시한다. |
| 4 | `Test/View`, Facility 씬 | 시간 경계와 대열을 자동 검사하고, 첫 진입과 다시 하기에서 화면과 입력을 확인한다. |

## 검증 시나리오

| 규칙 | 조건과 행동 | 기대 결과 |
|---:|---|---|
| 1 | Facility에 진입한다. | 네 졸개가 같은 줄에 서서 플레이어를 본다. 플레이어는 대열 중앙을 보고, 헬하운드는 현관에서 시작한다. 네 자리는 1층 로비 NavMesh 위에 있고 캐릭터끼리 겹치지 않는다. |
| 2 | 카운트다운 전체를 확인하며 이동·상호작용·Tab을 입력한다. | 숫자와 구도가 함께 바뀐다. 이동·상호작용·HUD 토글이 대기하고 숫자와 카메라가 바뀌는 동안 숫자를 읽을 수 있다. |
| 3 | `1`이 끝나는 프레임과 다음 프레임을 확인한다. | 카메라가 기존 탑다운 자세에 이어지고 중앙 숫자가 사라진다. `03:00`과 조작이 활성화되고 최초 시뮬레이션 Tick부터 시간이 줄어든다. |
| 4 | 타이틀 시작, 결과 화면 버튼·`R` 재시작, 시작 후 대화와 계단 이동을 확인한다. | 새 판마다 한 번 재생되고, 시작 후 기존 대화·계단 카메라와 일반 졸개의 로비 복귀가 동작한다. |

카메라 위치와 대열 간격은 Unity에서 벽·소품 가림, 캐릭터 간격, 화면비에 따른 숫자 표시를 확인한 뒤 확정한다.
