# 졸개 두뇌와 기억 스펙

- 상태: 확정
- 근거: GDD §5–7, U1·U2·U5·U6·U7·U9·U14·U101·U102, D2, `MinionAgent.md`
- 네임스페이스: `UnityGameJam.Minion`

## 목적

플레이어가 배정한 방에서 일반 졸개가 이동, 순찰, 청소를 반복한다. 관찰한 방의 상태와 다른 졸개의 담당 구역을 다음 방 선택에 사용한다.

## 입력과 출력

`MatchSetup.MinionBodies`, `FacilityLayout`, A1~A4의 오염·작업 선택·걸레·소화 서비스와 수치 에셋을 받는다. `MinionStatus`를 갱신하고 목표 방 제안이나 복귀 통보 요청을 A6에 보낸다.

## 규칙

1. 일반 졸개는 1층 로비에서 대기한다. 대화 중 멈추고 새 배정이 확정되면 작업 선점을 풀고 운반물을 현재 위치에 내려놓는다. 걸레가 있으면 빌린 화장실에 반납한 뒤 새 방으로 간다. 대화를 취소하면 기존 행동과 남은 작업 시간을 이어가고, 그 사이 대상을 잃었으면 다시 찾는다(U9). 소화는 대화 중에도 진행한다.
2. 방에 진입하고 확인한 작업을 먼저 고른다. 새 관찰은 배정 구역 안에서 XZ 거리 5m 이내이며 범위는 데이터 에셋에서 읽는다(U104). 돌아온 뒤에도 확인한 위치와 순찰 진도를 유지한다. 남은 작업이 보이지 않으면 기존 경로를 이어가고, 놓친 생성 지점은 가까운 곳부터 추가로 살핀다. 도달하지 못한 지점은 미확인으로 남긴다.
3. 처리할 수 있는 작업 중 졸개가 선호하는 유형을 우선하고, 같은 유형에서는 가까운 대상부터 고른다. 선호 작업은 판 시작 때 Decisions API에 한 번 요청하며, 가능한 작업이 하나뿐이거나 응답이 없으면 역할별 기본값을 사용한다. 대상에게 이동하기 전에 선점한다. 운반은 작은 물건이면 원래 슬롯, 폐기물이면 1층 현관 배출 지점에 놓는다. 그 뒤 원래 방에 복귀한다. 플레이어가 대상을 가로채거나 대상이 사라지면 현재 배정 구역에서 다시 판단한다.
4. 얼룩을 맡은 졸개만 걸레를 빌린다. 빌리러 가는 동안 대상이 사라지거나 선점을 잃으면 현재 배정 방에서 작업을 다시 찾는다. 같은 방에서 동료가 맡은 얼룩을 알고 있고 수행할 수 있는 다른 종류의 작업도 있으면 그 작업을 맡는다. 걸레가 있을 때는 얼룩만 닦고, 걸레를 반납하고 이어서 할 작업이 있으면 반납 전에 해당 작업을 선점한다. 일을 마치거나 재배정되면 빌린 화장실에 반납부터 한다. 슬라임은 소화 중에도 이동할 수 있고 소화가 끝날 때까지 새 작업을 시작하지 않는다. 기존 스냅샷의 `Digesting` 상태와 `Carrier=Slime`을 유지한다.
5. 이동은 `IMinionBody.MoveTo(층, 위치)`로 요청한다. `HasArrived`를 읽어 다음 행동으로 진행한다. B의 몸이 계단 이동과 `ViewSettingsSO`의 현재 2초 대기를 관리한다.
6. 배정받아 들어간 방을 직접 관찰한다. 두 졸개가 모두 로비 밖에 있고 같은 층에서 XZ 거리가 GameRuleSO의 상호작용 거리 이내일 때만 최신 방 정보를 교환한다. 전해 들은 내용은 직접 관찰과 구분한다. 다른 졸개가 일하는 위치와 화장실별 걸레 재고를 안다(D2).
7. 확인된 작업의 수량, 선호하는 작업, 동료 지원과 층간 이동 비용으로 다음 후보의 순위를 매긴다. 현재 방과 확인상 깨끗한 방을 제외한다. 후보가 없거나 제안이 보류·만료되면 로비로 간다.

## 설계

`MinionBrain`이 상태 전이, 목적지, 배정 ID를 관리한다. `MinionMemory`는 방별 관찰 기록만 보관하고 `ProposalCandidateFinder`가 후보를 고른다. 몸과 툴은 기존 계약과 서비스로 호출한다.

폐기물 운반 목적지는 1층 배출 구역의 바닥 중앙(X/Z는 Bounds.center, Y는 Bounds.min.y)이다. Facility에서 창고에 배정한 오크가 일반 쓰레기를 주워 배출 구역 안에 내려놓고 담당 방으로 복귀하는 것을 확인했다.
