# 작업 선택과 능력 스펙

- 상태: 확정
- 근거 문서: GDD §4, §5.1-3, §7.1–2 / `Undecided.md` U1·U7·U101
- 담당: A3 · A 레인
- 네임스페이스: `UnityGameJam.Minion`

## 목적

졸개가 배정받은 구역에서 자기 능력으로 할 수 있는 작업을 순서대로 고른다. 같은 유형끼리는 가장 가까운 개체를 고른다. 선택한 대상을 향해 이동하고 실제 작업을 시작하는 절차는 A5의 졸개 두뇌가 연결한다.

## 입력과 출력

| 구분 | 이름 | 설명 |
|---|---|---|
| 입력 | `WorkerStatsSO` | 작업자별 운반·물걸레질·소화 능력(자세한 값은 A2 에셋) |
| 입력 | 작업자·배정 구역·현재 위치·걸레 보유 여부 | 후보 범위와 작업 가능 유형 판단에 사용한다. |
| 입력 | `ContaminationRegistry.Items` | 오염 개체의 유형, 상태, 구역, 위치, 선점 정보 |
| 출력 | `ContaminationItem` 또는 없음 | 다음에 처리할 수 있는 개체 |

## 규칙

1. A2의 작업자별 데이터를 읽는다. 플레이어는 운반과 물걸레질을 모두 할 수 있다. 고블린은 작은 물건·일반 쓰레기 운반과 물걸레질, 오크는 세 운반 유형과 물걸레질, 스켈레톤은 물걸레질을 한다. 슬라임은 일반 쓰레기와 무거운 잔해를 먹고, 헬하운드는 일반 방 작업을 받지 않는다.
2. 졸개는 배정된 구역에 놓인 개체 중 **어질러진 작은 물건 → 무거운 잔해 → 일반 쓰레기 → 바닥 얼룩** 순서로 본다. 수행할 수 없는 유형은 건너뛴다. 같은 유형에서 여러 후보가 남으면 현재 위치에 가까운 순으로 고른다. 거리가 같으면 개체 ID가 작은 것을 우선해 결과를 재현할 수 있게 한다.
3. 걸레를 든 졸개에게는 얼룩만 후보로 남긴다. 걸레가 없는 졸개도 얼룩을 후보로 고를 수 있으며, 걸레 확보와 반납은 A4·A5에서 연결한다.
4. 다른 작업자가 실제 작업 중인 개체(선점 상태)와 운반·소화·처리 중이거나 처리된 개체는 졸개 선택에서 제외한다. 자기가 선점한 개체는 이어서 작업할 수 있다. 작업 선택은 상태를 바꾸지 않으며, 실제 작업을 시작할 때 A1 레지스트리가 선점과 플레이어 우선권을 적용한다(U7).
5. 졸개는 배출 구역의 적치 폐기물을 작업·제안 후보로 고르지 않는다. 슬라임은 로비 일반 바닥의 폐기물만 먹으며, 헬하운드가 적치 폐기물을 별도로 배출한다(U101).

## 예외 처리

- 적합한 후보가 없으면 결과를 반환하지 않는다. 다른 구역 탐색과 이동 제안은 A5·A6이 판단한다.
- 능력 데이터에서 작업자가 누락되거나 중복되면 초기화 오류로 처리한다. 능력을 구분할 수 없는 데이터로 작업 후보를 선택하지 않는다.

## 설계

| 파일 | 역할 |
|---|---|
| `Runtime/Minion/WorkerCapability.cs` | `WorkerStatsSO`를 작업자별로 찾아 `CanHandle`, `CanDigest`를 제공한다. |
| `Runtime/Minion/TaskSelector.cs` | 구역, 보유 걸레, 능력, 선점 및 오염 상태로 후보를 거른 뒤 유형·거리·ID 순으로 고른다. |
