# 청결도·오염 모델 스펙

- 상태: 확정
- 근거 문서: GDD §2, §3.1, §7.2, §8.1–2, §10 / `Undecided.md` U3·U7·U8 / `DesignIssue.md` D3
- 담당: A1 · A 레인
- 네임스페이스: `UnityGameJam.Cleaning`, `UnityGameJam.Facility`

## 목적

오염 개체의 상태와 위치를 기록하고, 판 시작 시 가중 오염량을 기준으로 구역별·시설 전체 청결도를 계산한다. A1은 오염 상태 전이와 집계의 기반을 제공한다. 초기 오염 생성과 데이터 에셋은 A2에서, 작업 능력과 선택은 A3에서, 도구·배출·소화 행동은 A4에서, 마감 호출과 성공 판정은 A7에서 연결한다.

## 입력과 출력

| 구분 | 이름 | 설명 |
|---|---|---|
| 입력 | `FacilityLayout` | 구역 및 층 경계, 1층 현관 배출 구역, 작은 물건의 제자리 슬롯 |
| 입력 | `ContaminationItem` | 판 시작 전에 등록하는 개체. ID, 유형, 가중치, 구역, 위치, 제자리 슬롯 ID를 가진다. |
| 입력 | `IWorkerBody` | 내려놓는 시점에 쓰는 작업자의 현재 위치와 층 |
| 출력 | `ItemSnapshot`, `ItemChanged` | 개체의 상태, 위치, 운반자 또는 소화 중인 작업자 |
| 출력 | `GetZoneCleanliness`, `GetFacilityCleanliness` | 구역별·시설 전체 청결도(0~100%) |

## 규칙

1. 판 시작에 각 구역과 시설 전체의 가중 오염량을 한 번 기록한다. 이후 같은 개체를 옮기거나 처리해도 시작 오염량은 그대로다. 현재 오염량은 `OnFloor`, `InDischargeArea` 개체의 가중치 합이다. `100 × (1 − 현재 오염량 ÷ 시작 오염량)`을 0~100%로 제한한다. 시설은 전체 가중 오염량으로 계산한다.
2. 일반 쓰레기와 무거운 잔해를 집으면 운반 중에는 양쪽 집계에서 빠진다. 내려놓으면 새 위치의 구역과 시설 전체에 다시 포함한다. 화장실이나 계단 등 판정 구역 밖에서는 작업자가 있는 층의 로비에 귀속한다(U8).
3. 일반 쓰레기와 무거운 잔해를 1층 현관 배출 구역에 내려놓으면 `InDischargeArea`가 되고 1층 로비 오염에 포함한다. 배출 시작 시점의 적치물만 `Dispatched`로 바꾼다. 로비 일반 바닥이나 나중에 적치된 개체는 그 묶음에 들어가지 않는다.
4. 슬라임이 일반 쓰레기와 무거운 잔해를 먹으면 `Digesting`이 되어 집계에서 빠진다. 한 번에 한 건만 소화하며, `Resolved`로 바뀔 때 점수를 다시 차감하지 않는다.
5. 바닥 얼룩을 닦거나 작은 물건을 자신과 짝지은 `HomeSlot`에 두면 `Resolved`가 된다(U3). 제자리 정리는 현재 운반자와 지정된 슬롯의 ID가 맞을 때 완료한다. 제자리까지의 접근 및 상호작용 범위는 후속 연결에서 판단한다.
6. 졸개는 실제 작업을 시작할 때 개체 하나를 선점한다. 다른 졸개는 선점된 개체에 작업을 시작할 수 없다. 플레이어는 바닥의 개체를 선점한 졸개에게서 우선권을 가져올 수 있다(U7). 운반 중이거나 처리된 개체에는 새 작업을 시작할 수 없다. 선점 후 작업자가 취소하거나 상태 전이를 마치면 선점을 해제한다.
7. 작은 물건도 운반 중에는 집계에서 제외한다. 중간에 내려놓거나 재배정되면 내려놓은 위치에 다시 귀속한다. 마감 때는 현재 위치에 귀속한 뒤 점수를 계산한다. 작은 물건을 배출 구역에 내려놓아도 바닥의 작은 물건으로 남는다(D3).
8. 후속 A7이 마감 직전에 운반물 내려놓기를 호출할 수 있게 한다. 작업자의 현재 위치·층으로 귀속하고 운반 중인 개체만 처리한다. 소화 중인 개체와 이미 출발한 배출 묶음은 그대로 집계에서 빠진다.

## 상태 전이

| 유형 | 가능한 전이 |
|---|---|
| 일반 쓰레기·무거운 잔해 | `OnFloor` 또는 `InDischargeArea` → `Carried` → `OnFloor` 또는 `InDischargeArea`. 슬라임에게 먹힌 폐기물은 `Digesting` → `Resolved`, 배출 시작 때 적치된 폐기물은 `InDischargeArea` → `Dispatched`. |
| 작은 물건 | `OnFloor` → `Carried` → `OnFloor` 또는 지정된 제자리에서 `Resolved`. |
| 바닥 얼룩 | `OnFloor` → `Resolved`. |

## 예외 처리

- 개체 ID가 없거나, 작업자·현재 상태·오염 유형이 맞지 않는 요청은 실패를 반환한다. 개체 상태와 집계를 바꾸지 않으며 `ItemChanged`도 발행하지 않는다. 같은 완료 요청을 반복해도 집계는 한 번만 바뀐다.
- GDD §3.1에 따라 판 시작에 판정 구역마다 가중치가 양수인 오염이 있어야 한다. 시작 오염량이 0인 구역이 있으면 판 시작 데이터를 검증할 때 오류로 처리한다.
- 구역 경계는 `FacilityLayout`의 해당 층 영역을 XZ 평면에서 확인한다. 화장실이나 계단 등 구역 밖을 표시할 때는 `ZoneMap`이 구역을 반환하지 않는다. 내려놓기 귀속에서만 층 로비를 적용한다.

## 설계

| 파일 | 역할 |
|---|---|
| `Facility/ZoneMap.cs` | `FacilityLayout`으로 위치가 속한 판정 구역을 찾고 내려놓을 때의 로비 귀속을 처리한다. |
| `Cleaning/ContaminationItem.cs` | 개체별 유형·가중치·제자리와 위치·구역·상태·운반자·선점을 보관한다. |
| `Cleaning/ContaminationRegistry.cs` | 오염 개체를 등록하고, 선점과 집기·내려놓기·제자리 정리·닦기·소화·배출의 상태 전이를 관리한다. 변경 확정 후 `ItemChanged`를 발행한다. |
| `Cleaning/CleanlinessCalculator.cs` | 시작 시 가중 오염량을 기록하고 레지스트리의 현재 상태를 조회해 청결도를 계산한다. |
