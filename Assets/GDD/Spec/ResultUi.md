# B7 마왕 도착과 결과 화면

**확정 · B 레인 · `UnityGameJam.UI`**
근거는 게임플레이 기획 §8.1·§8.2, `Spec/MatchFlow.md`, B 레인 실행 계획 B7, U12·U15·U17이다.

## 플레이 흐름

플레이어는 마감 순간에 운반하던 폐기물이 어디에 놓였는지 본 뒤, 성공 여부와 기준에 못 미친 구역을 결과 화면에서 확인한다.

| 시점 | 화면과 조작 |
|---|---|
| 1. 판 진행 중 | 기존 HUD를 표시한다. 다른 방의 최종 점수와 다시 하기 버튼은 숨긴다. |
| 2. 마왕 도착 | 타이머가 0이 되고 `DemonKingArrived`를 받으면 플레이 조작을 잠그고 배정 패널·제안 카드를 닫는다. 카메라를 1층 현관으로 전환한다. 문이 열리고 마왕이 걸어 들어온 뒤, 최종 판정에 따라 성공·실패 컷을 재생한다. |
| 3. 결과 표시 | 등장 연출이 끝나고 최종 결과가 준비되면 중앙의 `UI_ResultPanel`을 연다. 첫 줄에 ‘마왕 도착’과 ‘성공’ 또는 ‘실패’, 다음에 시설 전체 성적, 그 아래에 층별 9개 구역 성적을 표시한다. |
| 4. 다시 하기 | 결과 패널에서 ‘다시 하기’ 버튼을 누르거나 R을 새로 누르면 Facility 씬을 한 번 다시 불러온다. 새 판은 평소처럼 `MatchBootstrap`이 생성한다. |

마감 시 운반물의 귀속과 점수 계산은 A7이 끝낸다. 기존 `ContaminationView`가 최종 아이템 상태를 반영해 들고 있던 폐기물을 바닥에 표시한다. 작은 물건은 최종 점수에 귀속하며 전용 낙하 연출은 보류한다. 소화 중인 물건과 이미 배출을 시작한 묶음은 다시 나타나지 않는다.

## 현관 입장과 승패 컷

현재 1층 현관에는 4m 폭 문틀이 배치되어 있다. `FL_Floor1`의 현관에 기존 `ENV_WoodenDoorLeaf` 두 짝과 경첩, 마왕 입장 경로 및 배우 위치를 연결한다. 문 바깥의 첫발 아래에는 기존 바닥 타일을 이어서 깐다. 문과 배우 배치는 현관 프리팹 인스턴스에 맞춰 검증한다.

| 배우 | Unity에서 확인한 모션 | 컷에서 사용 |
|---|---|---|
| 마왕 `CH_DemonKing` | Animator의 `Walk → Walking` 1.03초, `Idle → Idle` 4초 | 보폭에 맞춰 문턱을 넘어 입장하고 멈춰 플레이어를 본다. |
| 플레이어 `CH_Player` | `Walking` 1.03초, `Idle_12` 6초, `PickUpHeavy → Female_Crouch_Pick_Throw_Forward` 4.87초 | 성공은 한 걸음 전진 뒤 대기 자세. 실패는 바닥의 쓰레기를 집어 마왕에게 던지는 동작. |
| 헬하운드 `CH_Hellhound` | `dog_run` 0.38초, `dog_idle` 1.58초, 원본 `dog_idle1` 7초 | 마왕 쪽으로 짧게 뛰어 다가간다. `dog_idle1` 앞부분의 꼬리 움직임을 사용해 반기는 동작을 보여 준다. |

아래 시간은 초안이다. 마왕의 이동 거리는 문턱 통과에 맞추고, 보행 재생 속도는 기존 보폭 계산을 사용한다.

| 컷 | 시점 | 화면과 모션 |
|---|---|---|
| 1. 현관 | 0–0.65초 | 1층 안쪽 바닥 높이에서 문 하단을 본다. 양쪽 문이 열리면 틈으로 마왕의 다리와 첫발이 먼저 보인다. |
| 2. 입장 | 0.65–2.65초 | 카메라가 마왕 앞에서 물러나며 발과 다리를 따라가다가 가슴 높이까지 올라 얼굴을 드러낸다. 헬하운드가 화면 가장자리에서 짧게 달려와 마왕 옆에 멈추고 꼬리를 흔든다. 마왕과 헬하운드는 한 프레임 안에서 읽히게 배치한다. |
| 3. 대면 | 2.65–3.25초 | 두 배우의 시선이 만나는 사선 투샷. 마왕은 `Idle`로 전환하고 플레이어는 마왕을 향해 몸을 돌린다. |
| 4. 성공 | 3.25–4.9초 | 플레이어가 마왕 쪽으로 한 걸음 다가가서 몸을 세운다. 카메라는 두 배우를 함께 담으며 조금 물러난다. |
| 4. 실패 · 두리번 | 3.25–4.45초 | 플레이어가 좌우에 모인 일반 졸개 네 마리를 차례로 훑어보고 마왕에게 다시 몸을 돌린다. 넓은 사선 프레임 안에서 양쪽의 거리를 보여 준다. |
| 5. 실패 · 투척 | 4.45–7.75초 | 플레이어가 바닥의 쓰레기를 집어 약 8m 떨어진 마왕을 향해 던진다. 카메라는 넓은 구도를 유지하고 쓰레기는 높은 포물선을 그린다. |
| 6. 실패 · 적중 | 7.75–8.48초 | 같은 구도에서 접촉을 약 0.11초 잡고 충격음과 마왕의 짧은 뒤젖힘을 맞춘다. 쓰레기가 발치로 떨어지는 동안 카메라가 조금 물러난다. |
| 결과 | 마지막 컷 후 | `UI_ResultPanel`에서 성공·실패, 청결도와 순위표를 표시하고 다시 하기 입력을 받는다. |

마감한 층에 관계없이 현관 컷으로 전환한다. 판정이 확정된 뒤 현관의 연출 위치에 플레이어와 헬하운드의 시각 모델을 놓는다. 실패 컷에는 일반 졸개 네 마리의 시각 모델도 배치한다. 사전 판정과 운반물 귀속은 기존 세션 위치를 사용한다. 다른 층 마감, 헬하운드 배출 중, 배정·계단 이동 중 마감에서도 같은 현관 컷을 재생한다. 연출 참조가 빠진 씬은 기존 결과 표시 경로를 사용한다.

`DemonKingArrivalView`가 문, 배우 위치, 컷 타이밍과 결과 공개를 진행한다. `FloorCameraFollow`에서 오프닝과 같은 메인 카메라로 화면을 전환한다. `ViewSettings`에서 컷 시점과 구도를 조정한다. 기존 Animator의 보행·대기 상태와 클립 샘플링을 사용해 연출의 재생 시각을 맞춘다. 투척 쓰레기는 연출용 시각 모델로 배치하고 마감 판정과 순위는 앞서 확정한 결과를 사용한다.

## 결과 패널

- 전체 성공·실패는 `MatchResult.IsSuccess`, 시설 점수는 `FacilityCleanliness`, 구역별 점수는 `ZoneCleanliness`에서 읽는다.
- 각 행에 이름, 최종 청결도, 기준값, ‘통과’ 또는 ‘미달’을 표시한다. 판정에는 표시 전 원값과 세션의 `FacilityThreshold`·`ZoneThreshold`를 사용한다. 퍼센트 표시는 기존 HUD처럼 정수로 내림한다. 현재 `GameRule.asset`의 기준은 시설 85%, 구역 60%다.
- 행은 1층 로비·다목적실·휴게실·창고, 2층 로비·회의실·작업실, 3층 로비·간부실 순서로 배치한다. 이름과 층은 `ZoneDisplayName`을 사용한다.

## 구현 연결과 경계 조건

- `DemonKingArrivalView`는 `MatchBootstrap.MatchStarted`에서 세션에 연결하고 `MatchStateChanged`를 구독한다. 활성화 시 이미 시작된 세션의 현재 상태도 읽고 비활성화 시 구독을 해제한다. 마왕 프리팹은 인스턴스를 생성해 표시한다.
- 실제 판과 가짜 판 모두 한 번의 `Tick` 안에서 `DemonKingArrived`와 `Resolved`를 차례로 알린다. 도착 이벤트에서 연출을 시작하고 `Resolved`에서 결과를 보관하고 성공·실패 컷을 고른다. 연출 완료와 결과 수신이 모두 충족되면 `ResultPanel`을 한 번 연다. 이미 종료된 판에 뒤늦게 연결되면 저장된 결과를 표시한다.
- 마감과 배정 패널 닫힘이 겹쳐도 이동·상호작용·제안 응답 입력은 잠긴 상태를 유지한다. 결과가 표시된 뒤 새로 누른 R만 재시작 입력으로 받는다. 버튼과 키가 동시에 들어와도 씬 로드는 한 번만 요청한다.

## 구현 후 검증

| 규칙 | 검증 장면 | 기대 결과 |
|---|---|---|
| 1·2 | Facility에서 폐기물을 든 채 180초 마감. 다른 층과 배정 대화 중 마감도 확인 | 1층 현관에서 등장 컷이 재생된다. 운반물은 마감 위치에 놓이고, 플레이 입력과 배정·제안 UI는 닫힌다. |
| 2·3 | 가짜 세션에서 같은 틱에 도착·판정 이벤트 발생 | 문 열림, 첫발, 얼굴 공개, 헬하운드 반응, 승패 컷 순서로 진행되고 결과 패널 하나가 열린다. 재활성화 시 중복되지 않는다. |
| 3 | 시설 85%, 모든 구역 60% 이상 | 성공. 시설과 9개 구역에 모두 ‘통과’가 표시된다. |
| 3 | 시설 90%, 3층 로비 59%. 별도 판에서 모든 구역 통과, 시설 84.9% | 첫 판은 3층 로비, 두 번째 판은 시설 행이 ‘미달’이며 둘 다 실패다. |
| 4 | 마감 전부터 R 유지 → 결과에서 키를 뗐다가 다시 누름. 별도로 버튼 클릭 | 결과를 읽을 수 있고 새 입력마다 한 판만 시작한다. 타이머와 HUD가 초기화되며 이전 결과·마왕은 사라진다. |

## 적용 범위

이번 판은 U12의 결과 화면과 다시 하기, U17의 마왕 등장을 사용한다. 마왕의 등장 보행과 대기에는 `CH_CrimsonHoodedMage` FBX를 사용한다.


## 전체 청소 완료와 이 PC 순위표

사용자 확정 · 2026-11-19

- 시설 전체 청결도가 100%이고 바닥·현관 적치·운반 중인 오염이 없으면 완료 시각을 기록한다. 소화 중·배출 출발·처리 완료는 기존 최종 판정 기준을 따른다.
- 완료 시각은 판 시작부터 완료 순간까지의 게임 시간이다. 남은 카운트다운은 ViewSettingsSO의 CompletionCountdownSeconds 동안 빠르게 넘긴 뒤 기존 마왕 도착과 결과 화면으로 이어진다. 초기 연출값은 2초이며 에셋에서 조절한다.
- 카운트다운 연출 중에는 플레이어의 이동과 상호작용을 멈춘다. 전역 Time.timeScale은 바꾸지 않는다.
- 100% 완주 기록을 먼저 배치하고 완료 시간이 빠른 순으로 정렬한다. 미완주 기록은 최종 시설 진행도가 높은 순으로 배치한다. 같은 값의 기록은 고유 기록 ID 순으로 고정한다.
- 이 PC의 Application.persistentDataPath/leaderboard.json에 매 판 한 건을 저장한다. 파일 교체 전 임시 파일을 쓰고 이전 파일을 bak으로 보관한다. 다시 읽어도 기존 기록이 유지되며 결과 화면 재표시로 같은 판이 중복 등록되지 않는다.
- 결과 화면에서 이번 기록과 순위, 상위 10건을 표시한다. 진행도는 소수 두 자리까지 표시하고 완료 시간은 분·초·소수 두 자리로 표시한다.
- 검증은 운반 중 100% 자동 종료 방지, 실제 완료 카운트다운, 완주 시간순·미완주 진행도순과 저장 재독출에 한정한다.
